# 魔法运动员 · 中文电脑版

二维中文多人游戏：36 位运动员、双面赛道、2–6 人、四场比赛、自动技能结算与私密出场选择。支持本地同机，以及由独立服务器结算和保存的好友房联机模式。原创 SVG 图案随项目保存，不依赖外部图片。

好友房的玩法、个人恢复码、7 天保存策略、服务器部署和备份恢复见 [联机使用说明](docs/online.md)。实际验证范围见 [验证记录](docs/verification.md)。

## 启动与停止

在项目目录执行 `./start.sh`，然后打开 <http://127.0.0.1:5173>，使用本地同机模式。脚本优先使用系统 Node.js；若已安装 Codex，也会自动查找其已有运行时。首次安装需要联网，同机游玩只需要本机服务。好友联机需要启动独立服务端或打开已部署的游戏网址；没有 AI、公开匹配或桌面安装包。

```sh
cd magical-athlete && ./start.sh
```

- 查看状态：`./start.sh status`
- 查看最近日志：`tail -n 100 logs/dev.log`
- 持续查看输出：`tail -f logs/dev.log`，按 Ctrl+C 只退出日志查看。
- 停止本项目服务：`./start.sh stop`
- 前台运行（在终端直接看输出）：`pnpm dev`，先停止后台服务以释放端口。

本地启动器采用独立后台进程。PID 保存在 `logs/dev.pid`；状态保存在 `logs/dev.status.json`；真实退出码保存在 `logs/dev.exit`。服务严格绑定 `127.0.0.1:5173`，端口被占用时明确失败，不自动切换端口导致存档看似丢失。重新开机后重新运行启动脚本。

## 玩法

1. 设置 2–6 位玩家；2 人自动使用双角色规则，3 人可选双角色变体。
2. 按界面顺序招募；每场私密选择尚未出场的运动员。双角色的点击顺序即本场行动顺序。
3. 交接屏幕后确认出场，全部选好再揭示。点击「开始回合」，遇到可选技能按提示决定。
4. 四场依次温和、狂野、温和、狂野。金/银奖励为 3/1、4/2、4/2、5/3；最高总分相同共享胜利。
5. 动画可以正常、快速或关闭；关闭不改变规则。角色图鉴可随时搜索，结算记录解释每次变化。

## 存档与隐私

以下 JSON 导入导出与 IndexedDB 说明适用于同机模式。好友房由服务器保存，各玩家只能收到本人有权查看的信息；刷新通过浏览器会话恢复，换电脑使用个人恢复码，联网房间不能用本地 JSON 覆盖。

每次操作后自动保存到当前浏览器 IndexedDB。看到「已自动保存」后即可关闭；重开选择「继续上次游戏」。未完成的技能选择也能恢复。浏览器数据清理、不同浏览器或不同地址不共享存档，建议导出 JSON 备份。

导入会检查版本、阶段、角色引用及待结算任务，确认覆盖后替换当前存档。游戏状态在操作前复制；非法或重复操作不会再次计分。存档含完整游戏状态及尚未揭示的选择，属于本地私人备份；同机遮挡防止界面意外泄露，不提供对本机开发者工具的防作弊保证。

## 规则依据与明确解释

规则基准为 CMYK 36 角色基础盒与 2026-08-28 FAQ；详见 [规则核对记录](docs/rules.md)。规则书中的旧英文隐藏层未直接用作数据来源。

三个未被原文完全展开的边界策略已明示在规则记录中：模仿猫独自领先时无额外能力；蛋蛋抽出的三张移出未用牌堆；吸盘鱼按英文 move 允许跟随后退。这些不是发行商额外确认的裁定。基础盒全部角色均有实现，不用人工裁定代替未写的能力。

## 开发与验证

技术：React、TypeScript、Vite、Vitest、Playwright；联机服务使用 Socket.IO 与 Node 内置 SQLite。使用 Node.js 24、pnpm 11.19.0；依赖由 `pnpm-lock.yaml` 固定。没有 Python 运行时依赖。

```sh
pnpm install --frozen-lockfile && pnpm test && pnpm build
```

浏览器测试需要先启动本地服务，再运行 `pnpm test:e2e`。配置优先使用 `CHROME_PATH` 指定的 Chrome，否则使用 Playwright Chromium；macOS 也可使用已安装的 Google Chrome。

- `src/game`：独立规则与内容；`GameState`、`GameAction`、`GameEvent`、`PlayerView` 为核心边界。
- `src/session`：会话适配、IndexedDB 与本地存档校验；联机客户端通过异步请求提交命令和接收可见状态。
- `server`：联机房间、身份、权限校验与事务存档；完整联网游戏状态只在服务端执行。
- `src/ui`：棋盘、原创图案、动画回放；动画快照只作展示，不回写规则。
- `tests`：每名角色基础机制、官方组合裁定、人数模式整局、存档往返与浏览器流程。

规则按事件队列逐步结算，暂停点可序列化；相同种子与操作可复现。超过单批处理预算的长连锁会保存并提供「继续结算」，不以任意技能次数上限改写比赛。
